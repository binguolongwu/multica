## 1. 项目概览

**Multica 是一个 AI 原生的任务管理平台**——可以理解为「以 AI agent 为一等公民的 Linear」。

核心理念:

- AI agent 与人类成员平权:agent 可被指派 issue、创建 issue、发表评论、变更状态、担任项目 lead。
- 支持两种 agent 运行时:**本地 daemon 运行时**(当前唯一生产可用)与**云运行时**(waitlist,未上线)。
- 面向 2–10 人的 AI 原生小团队。

**最关键的架构判断**:Multica 是一个分布式系统,**服务端只做协调**(存储数据、排队任务、通过 WebSocket 实时推送),**从不执行 agent 任务**。任务由用户机器上的 daemon 拾取并驱动本地 AI CLI(Claude Code、Codex 等)真正执行。这是它与 Linear/Jira 的本质区别——「agent 不在我们服务器跑,在你机器跑」。

四种触发方式产生统一的 task,经队列分发到对应 runtime:

1. **指派 issue 给 agent**(重触发:agent 拿到完整 issue + 所有评论上下文)
2. **`@` 提及 agent**(轻触发:以该评论为上下文)
3. **Chat**(与单个 agent 的一对一私密沙箱会话)
4. **Autopilot**(时间/触发器驱动的自动化)

```
                                │                    │
   ┌──────────┐  HTTPS/WSS  ┌───▼────────────────────▼───────────────┐
   │  Web     │────────────▶│         Go 后端 (server)                 │
   │ (Next.js)│             │  Chi 路由 · sqlc · gorilla/websocket     │

                                   │  PostgreSQL (pg17)        │
                                   │  pgcrypto/pg_bigm/pg_cron │
                                   └───────────────────────────┘
                                   (可选 Redis:多节点实时 relay
                                    + PAT/daemon token 缓存)
```

**前端 monorepo 依赖方向**:`apps/{web,desktop} → packages/views → packages/core + packages/ui`。`core` 与 `ui` 互不依赖。这是保证跨平台复用的硬约束。

- `packages/core/`:无头业务逻辑(Zustand store、TanStack Query hooks、API client、平台桥)。零 react-dom、零 localStorage、零 process.env。
- `packages/ui/`:原子 UI 组件(Base UI/shadcn)。零 `@multica/core` 导入。
- `packages/views/`:共享业务页面/组件。零 `next/*`、零 `react-router-dom`,通过 `NavigationAdapter` 路由。
- `apps/web/platform/`:唯一允许使用 Next.js API 的地方。
- `apps/desktop/src/renderer/src/platform/`:唯一允许使用 react-router-dom 的地方。

**Internal Packages 模式**:所有共享包导出原始 `.ts`/`.tsx`(无预编译),由消费方打包器直接编译,带来零配置 HMR 与即时跳转定义。`pnpm-workspace.yaml` 的 `catalog:` 锁定共享依赖单一版本。

## 5. 后端(Go)详解

### 5.1 进程 / 二进制划分

| 二进制 | 入口 | 职责 | 运行 |
|---|---|---|---|
| **server** | `cmd/server/main.go` | HTTP API + WebSocket + 所有后台调度器 goroutine | `make server`(默认 8080) |
| **multica**(CLI) | `cmd/multica/main.go` | Cobra 命令树 + 本地 daemon 运行时 | `make cli ARGS="..."` |
| **daemon**(CLI 子命令) | `cmd_daemon.go` → `internal/daemon/` | 注册 runtime、认领并执行任务、心跳、自更新 | `make daemon` |
| **migrate** | `cmd/migrate/main.go` | 顺序执行迁移,`schema_migrations` 跟踪版本 | `make migrate-up/down` |
| **backfill** ×2 | `cmd/backfill_task_usage_{daily,dashboard_daily}` | 一次性回填用量汇总表 | 手动(支持 `-dry-run`) |

**server 启动顺序**:`logger.Init` → 校验配置 → 建 `pgxpool` → 建事件总线/实时 Hub/daemon Hub → 可选 Redis relay(`REALTIME_RELAY_MODE` 默认 `sharded`)→ 按**严格顺序**注册监听器(listeners → subscriber → activity → notification,因通知监听器依赖订阅表)→ 构建心跳调度器 → 建 chi 路由 → 启动后台 goroutine → 优雅关停(先排空 HTTP,再 flush 最后一批心跳)。

### 5.2 分层架构

调用链:**HTTP → middleware → handler → service → db(sqlc)**

- **Handler 层**(`internal/handler/`):核心 `Handler` 结构体持有 `Queries`、`Hub`、`DaemonHub`、`Bus`、`TaskService`、`AutopilotService`、各种 Store/Cache。辅助方法:`publish*`(发事件)、`resolveActor`(判定 member vs agent,**要求同时携带有效 `X-Agent-ID`+`X-Task-ID` 且 task 属于该 agent**,防成员冒充)、loader(`loadIssueForUser`/`loadAgentForUser` 等,支持 `MUL-123` 或 UUID)。文件按领域拆分(issue.go / agent.go / runtime.go / daemon_ws.go / autopilot.go / squad.go / chat.go ...)。
- **Service 层**(`internal/service/`):`TaskService`(入队/认领/生命周期/重试/daemon 唤醒)、`AutopilotService`(派发/重复跳过)、`cron.go`(`ComputeNextRun`)、`email.go`。
- **DB 层**(`server/pkg/db/`):`queries/*.sql`(30 个领域文件)由 sqlc 生成 `generated/*.sql.go`;`WithTx(tx)` 支持事务内查询。
- **Middleware 层**(`internal/middleware/`):

| 中间件 | 职责 |
|---|---|
| `RequestID`/`ClientMetadata`/`RequestLogger` | 请求 ID、客户端平台/版本、结构化访问日志 |
| `Recoverer`(chi) | panic → 500,进程不崩(UUID 解析约定依赖此) |
| `Auth` | session JWT(`multica_auth` cookie,写操作强制 CSRF)或 PAT(`mul_`,经 `PATCache`) |
| `DaemonAuth` | daemon token(`mdt_`)→ PAT → JWT 回退链 |
| `RequireWorkspaceMember`/`RequireWorkspaceRole` | 解析 workspace(slug 优先→UUID 回退)+ 成员/角色 gate |

### 5.3 HTTP API 路由总览(`cmd/server/router.go`)

**公开/无 Multica 鉴权**:`/health` `/readyz` `/healthz`、`/health/realtime`、`/ws`(浏览器实时 WS,membership + PAT/JWT 校验)、`/auth/send-code|verify-code|google|logout`、`/api/config`、`/api/webhooks/github`(HMAC 签名校验)、`/uploads/*`。

**Daemon API**(`/api/daemon/*`,`DaemonAuth`):`register|deregister|heartbeat`、`/ws`(daemon WS)、`runtimes/{id}/tasks/claim|pending`、`tasks/{id}/start|progress|complete|fail|usage|messages`、`*/gc-check`、`recover-orphans`、`tasks/{id}/session`(会话续接 pin)。

**受保护 API**(`Auth`,session cookie 或 PAT):

| 领域 | 主要端点 |
|---|---|
| 用户级 | `/api/me`、`/api/cli-token`、`/api/upload-file`、`/api/feedback`、`/api/workspaces`、`/api/invitations/*`、`/api/tokens`(PAT) |
| Issues | `/api/issues`(search/grouped/quick-create/batch-update/batch-delete);`/api/issues/{id}/...`(comments/timeline/subscribe/active-task/rerun/usage/reactions/attachments/children/labels/pull-requests) |
| Comments/Labels/Projects | `/api/comments/{id}`(update/delete/resolve/reactions);`/api/labels/*`;`/api/projects/*`(含 resources) |
| Squads/Autopilots/Agents | `/api/squads/*`;`/api/autopilots/*`(trigger/runs/triggers);`/api/agents`(create/from-template/archive/cancel-tasks/skills) |
| Runtimes/Chat/Inbox | `/api/runtimes/{id}/...`;`/api/chat/sessions/*`;`/api/inbox`(unread-count/mark-all-read/archive) |
| Dashboard/Usage | `/api/usage/{daily,summary}`、`/api/dashboard/usage/{daily,by-agent}` |

workspace 解析优先级:context → `X-Workspace-Slug` 头 → `?workspace_slug` → `X-Workspace-ID` 头 → `?workspace_id`。角色门控用 `RequireWorkspaceRoleFromURL(...,"owner","admin")`。

### 5.4 实时与事件机制

**两类 WebSocket**:

| 端点 | 实现 | 用途 |
|---|---|---|
| `GET /ws` | `internal/realtime` | 浏览器实时推送。PAT/JWT 认证 + membership 校验,自动订阅 `workspace:{id}`/`user:{id}`,慢客户端被驱逐 |
| `GET /api/daemon/ws` | `internal/daemonws` | Daemon 连接。按 runtime ID 索引;仅做尽力而为的任务唤醒(`daemon:task_available`)与 WS 心跳;任务认领仍走 HTTP 保证正确性 |

**事件系统**(`internal/events/bus.go`):进程内同步 pub/sub,按注册顺序调用,每个 handler 用 `recover` 隔离。事件类型常量集中于 `pkg/protocol/events.go`。

**监听器**(`cmd/server/*_listeners.go`):`listeners.go`(WS 广播,个人事件仅 `SendToUser`)、`subscriber_listeners.go`(维护订阅表)、`activity_listeners.go`(写 `activity_log`)、`notification_listeners.go`(生成 `inbox_item`)、`autopilot_listeners.go`(回写 autopilot run 状态)。

**心跳与运行时清扫**:

- `runRuntimeSweeper`(30s):标记 >150s 无心跳的 runtime 离线(Redis liveness store 二次过滤)、失败孤儿任务、过期 queued 任务(>2h)、GC 离线 >7 天的 runtime。
- `BatchedHeartbeatScheduler`(30s):把「已 online 仅 bump last_seen_at」合并为一次批量 UPDATE;状态翻转走同步路径立即提交。

### 5.5 Agent 任务执行引擎

1. **入队**:`TaskService.EnqueueTaskFor{Issue,Mention,SquadLeader}` 建 `agent_task_queue` 行(`queued`),广播 `task:queued`,经 daemon WS hub 发 `daemon:task_available` 唤醒。
2. **唤醒**:daemon 拨 `/api/daemon/ws`,收到提示后认领;WS 不可用则退化轮询。
3. **认领**(`tasks/claim`):Redis `EmptyClaimCache` 空命中快路径;`ListQueuedClaimCandidatesByRuntime` 取候选,按 agent 去重逐个原子 `ClaimTask`;响应注入新鲜 agent 配置 + workspace 仓库(+ squad leader briefing)。
4. **生命周期**:`StartTask` → `ReportProgress/Messages` → `CompleteTask`(chat 任务在单事务内同时更新会话续接指针)/`FailTask`。
5. **超时/重试**:无显式租约,由 sweeper 兜底(`dispatched`>300s、`running`>9000s 强制失败);`MaybeRetryFailedTask` 仅对基础设施类失败(`runtime_offline`/`runtime_recovery`/`timeout`)派生子任务自动重试,受 `attempt < max_attempts`(默认 2)约束;autopilot 任务不自动重试。
6. **会话续接**:`PinTaskSession` 两次锁定 session ID;手动 `RerunIssue` 置 `force_fresh_session=true` 起全新会话。

`pkg/agent/` 含 claude/codex/copilot/cursor/gemini/kimi/kiro/opencode/pi/hermes/openclaw 等 provider 适配 + 版本检测。

### 5.6 核心后台调度器

| 调度器 | 周期 | 职责 |
|---|---|---|
| `runRuntimeSweeper` | 30s | stale runtime/task 清扫、queued 过期、runtime GC |
| `BatchedHeartbeatScheduler` | 30s | 批量刷新心跳 last_seen_at |
| `runAutopilotScheduler` | 30s | 认领到期触发器并 `DispatchAutopilot`,推进 next_run_at |
| `runAutopilotFailureMonitor` | 默认 24h | 7 天回看窗内运行数≥50 且失败率≥0.9 的 autopilot 自动暂停并通知 |
| `runDBStatsLogger` | 周期 | 记录连接池统计 |

### 5.7 安全与多租户

- **鉴权三态**:Session JWT(`multica_auth` cookie,30 天,写操作 CSRF 校验)/ PAT(`mul_`,SHA-256 哈希,`PATCache`)/ Daemon token(`mdt_`,绑定单一工作区)。
- **多租户**:所有 workspace 级查询经 `RequireWorkspaceMember/Role` 中间件,SQL 普遍带 `workspace_id` 过滤;loader 用 `Get*InWorkspace` 双重校验。
- **Agent 防冒充**:`resolveActor` 要求 `X-Agent-ID`+`X-Task-ID` 双重证明。
- **UUID 解析约定**(对应 CLAUDE.md):`parseUUID` 是 panic 变体(仅用于可信回程,panic 由 Recoverer 转 500);`parseUUIDOrBadRequest` 用于请求边界(失败写 400);标识符/UUID 路径参数必须经 loader 解析后用 `entity.ID` 做写查询。规避了 #1661(DELETE 返 204 但匹配 0 行)。
- **`redact` 包**:agent 输出落库/广播前正则掩码 AWS/GitHub/Slack/OpenAI/Anthropic key、PEM、JWT、含密码连接串、env 风格 `KEY=value`,并掩码 home 路径用户名。

## 6. 前端共享包详解

### 6.1 packages/core(无头业务逻辑)

**平台桥 `platform/`**:`CoreProvider` 是每个 app 的根包裹器,模块级单例 `initCore` 只执行一次,初始化顺序:`ApiClient` 单例 → schema logger → token 注水 → `createAuthStore` → `createChatStore`。渲染树:`I18nProvider` → `QueryProvider` → `AuthInitializer` → `WSProvider` → children。

`setCurrentWorkspace(slug, wsId)` 是「当前工作区」的**唯一真相源**(配对 `_currentSlug`/`_currentWsId` 模块变量);slug 变化通过 `queueMicrotask` 延迟触发 WS 重连 + persist store rehydrate;slug 相等是纯 no-op(desktop 多 tab 友好)。

`StorageAdapter` 抽象:`defaultStorage`(SSR 安全 localStorage 包装)、`createWorkspaceAwareStorage`(按 `${key}:${slug}` 命名空间隔离,无 slug 时写丢弃,防跨工作区泄漏)。

**API client 与防御式解析**:`ApiClient`(`api/client.ts`,~1.5k 行)单例,`authHeaders()` 注入 `X-Workspace-Slug` 实现多租户路由。**防御边界**:`parseWithFallback<T>(data, schema, fallback)` 用 zod `safeParse`,失败时 `schemaLogger.warn` 并返回 fallback,**永不抛进 UI**;`api/schemas.ts` 对高风险端点(timeline/comments/subscribers/issues list——历史白屏面 #2143/#2147/#2192)定义宽松 schema(枚举用 `z.string()`、对象 `.loose()`、数组默认 `[]`)。

**状态管理双轨**:

- TanStack Query(`query-client.ts`):`staleTime: Infinity`(WS 失效驱动)、`gcTime: 10min`、`refetchOnWindowFocus: false`。query key 工厂按域组织(`issueKeys`/`workspaceKeys`/...),所有工作区作用域 key 以 `wsId` 开头,切换工作区自动换数据。mutations 实现乐观更新。
- Zustand store(全部在 core):`auth/store.ts`、`chat/store.ts`、`issues/stores/*`(selection/view/draft/recent...)、`navigation/store.ts`(lastPath persist)、`modals/store.ts`、`config/index.ts` 等。工作区作用域 persist store 通过 `createWorkspaceAwareStorage` + `registerForWorkspaceRehydration`。

### 8.2 本地 Daemon 工作原理

daemon 是 CLI 的一部分,所有调用走 `/api/daemon/*`(带 daemon token / PAT 鉴权头)。

**启动四步**:① 读凭据 → ② 检测 PATH 上已装的 11 个 AI CLI(Claude Code/Codex/Cursor/Copilot/Gemini/Hermes/Kimi/Kiro/OpenCode/OpenClaw/Pi)→ ③ 为每个(工作区 × 工具)`POST /api/daemon/register` 注册一个 runtime → ④ 轮询拾取 + 心跳。**runtime = daemon × 一个 AI 工具**。

**任务循环**:`pollLoop` 默认 3s 调 `tasks/claim`,另有 WS 唤醒通道(`/api/daemon/ws`)即时推送。认领后 `tasks/{id}/start` → 创建隔离工作目录(`~/multica_workspaces`)spawn AI CLI → 流式回传 `progress`/`messages`/`usage` → `complete`/`fail`。心跳默认 15s,45s 无心跳标记 missing。并发两层:daemon 层默认 20,agent 层默认 6,取较紧者。

**会话续接**:`tasks/{id}/session` 两次锁定 session ID(崩溃恢复 + 自动重试续接);手动 rerun 故意起全新会话。真正可用续接:Claude Code/Copilot/Hermes/Kimi/Kiro/OpenCode/OpenClaw/Pi;MCP 仅 Claude Code 真正消费。

**崩溃恢复与 GC**:启动调 `recover-orphans` 让服务端标 `runtime_recovery`;`gcLoop` 按 `*-gc-check` 三种回收(满 TTL 整目录删 / 孤儿删 / open issue 仅删可再生产物保留源码与 `.git`)。

## 9. 数据库 Schema 说明

> 来源:`server/migrations/*.up.sql`(001–090,~90 个迁移)+ `server/pkg/db/queries/*.sql`(30 个,与表/领域一一对应)。

### 9.1 Schema 总览

**扩展**:`pgcrypto`(`gen_random_uuid()` 主键默认值)、`pg_bigm`(bigram 全文检索,CJK 友好,用 `DO/EXCEPTION` 包裹兼容无扩展 CI)、`pg_cron`(调度用量日汇总)。**未使用 pgvector**(尽管开发镜像是 pgvector,当前无 vector 列)。

**多租户**:几乎所有业务表带 `workspace_id UUID NOT NULL REFERENCES workspace(id) ON DELETE CASCADE`,删 workspace 级联清除全部数据。

**命名约定**:单数 snake_case 表名;`"user"` 因保留字加引号;主键统一 `id UUID DEFAULT gen_random_uuid()`;时间戳 `TIMESTAMPTZ DEFAULT now()`;软归档用 `archived_at`+`archived_by`;**枚举一律 `TEXT + CHECK (col IN (...))`**(非 PG ENUM,便于演进);**多态关联**普遍用 `<role>_type TEXT CHECK(...)` + `<role>_id UUID`(无外键,应用层解析)。

### 9.3 关键关系

- **多态 assignee/actor**:`<type>+<id>` 二元组(无 FK)贯穿全库:issue assignee(member/agent/squad)、comment author、activity actor(+system)、inbox recipient、subscriber、reaction、attachment uploader、project lead、squad member。
- **issue ↔ task ↔ runtime ↔ agent**:`agent_task_queue` 串联 issue(可空)/chat_session/autopilot_run/trigger_comment/parent_task,`agent.runtime_id` 与 `task.runtime_id` 均 NOT NULL FK;用量经 `task → agent → workspace` 解析(刻意走 agent 而非 issue)。
- **squad ↔ agents**:`squad.leader_id → agent`(RESTRICT);`squad_member` 多态;`is_leader_task` 区分 leader/worker 角色防自触发。

### 9.4 值得注意的设计决策

1. **任务用量三层汇总 + pg_cron**:原始 `task_usage` → 按 runtime `task_usage_daily` → 按 agent/project `task_usage_dashboard_daily`;幂等 `rollup_*_window()` 函数从原始数据**重算**(非增量),`pg_try_advisory_lock` 串行化;`*_dirty` 触发器队列捕获 DELETE/重指派;bucket 按 runtime 时区且不回填历史。
2. **全文检索**:pg_bigm GIN 索引基于 `LOWER(col)` 表达式(兼容 RDS pg_bigm 1.2 无 ILIKE 索引扫描)。
3. **预留 slug 审计迁移**(043/045/047/049/056):校验 `workspace.slug` 不与前端顶级路由冲突,冲突则 `RAISE EXCEPTION` 阻断部署或自动重命名。
4. **任务租约/重试列**(055/066/069/090):区分首次执行 vs 孤儿自动重跑;`force_fresh_session` 让手动 rerun 跳过会话续接。
5. **在线安全迁移技巧**:热表索引用 `CREATE INDEX CONCURRENTLY`(独立单语句文件);长度约束 `ADD CONSTRAINT NOT VALID` + 单独 `VALIDATE`;新增列默认值分步避免全表重写。
6. **已废弃表**:`daemon_pairing_session`(005→029 删)、`runtime_usage`(013→046 删,但 `runtime_usage.sql` 查询文件仍在)。

### 10.1 工作项

- **Workspaces**:协作自包含空间;name 可改、slug/issue prefix 创建后勿动;删除不可逆。
- **Members & roles**:owner/admin/member 三角色;member 不能邀人;只有 owner 能授 owner;邀请 7 天有效;永远至少一个 owner。
- **Issues**:核心工作单元(title/description/status/priority/assignee/可选 project);**assignee 可为人或 agent**;7 状态任意跳转;workspace 内唯一编号 `MUL-123` 永不变;推荐改 `cancelled` 而非删。
- **Projects**:关联 issue 的容器,有 lead(人/agent)、5 状态、自动进度;删项目不删 issue;可个人 pin 到侧栏。
- **Project resources**:项目附加类型化指针(今 `github_repo`);agent 跑该项目 issue 时 daemon 自动写 `.multica/project/resources.json`;项目有 repo 则覆盖工作区 repo 列表。
- **Comments**:评论树,Markdown + 嵌套回复 + reaction + `@` mention + `@all`;`@` agent 触发其工作(编辑加 `@` 不触发)。
- **Labels**:工作区标签 CRUD。

### 10.2 AI 协作

- **Agents**:工作区一等成员,背后是本机 AI 工具;可被指派/发评论/被 `@`/当 lead/自建 issue;不收 inbox 通知;绑定一个 runtime;可归档(归档即取消未完成任务);可见性 workspace/private(默认 private)。
- **创建/配置 agent**:必填仅 name + AI 工具;可选 instructions、model、`custom_env`(明文存库,勿放高价值密钥)、`custom_args`、visibility、`max_concurrent_tasks`(默认 6)、attached skills。
- **Skills**:知识包(`SKILL.md`+附件),兼容 Anthropic Agent Skills 标准;workspace skill(云存共享)vs local skill(本机扫描);来源 New/GitHub/ClawHub/local;第三方技能不沙箱需自审。
- **Squads**:agent(可含人)的命名组,有一个 leader agent;squad 本身是一等 assignee;指派后 leader 读 issue 并 `@` 最合适成员;提供按主题而非按名字的路由。

### 10.3 自动化与触发

- **Assigning issues**:最重触发——换 assignee,agent 拿全 issue + 所有评论上下文;Backlog 状态指派不触发;可重试。
- **Mentioning agents**:轻触发——不改 assignee/status,以该评论为上下文;一评论可 `@` 多 agent 并行;直接自我 `@` 防循环。
- **Chat**:与单个 agent 一对一私密沙箱(看不到/改不了任何 issue,他人含 admin 看不到);多轮靠 session 续接。
- **Autopilots**:cron(5 字段,IANA 时区)+ 手动 trigger;两模式 `create_issue`(推荐)/`run_only`;失败不自动重试不通知;服务端每 30s 扫(触发可滞后 30s)。
- **Tasks**:每次 agent 运行单元;状态机 queued→dispatched→running→completed/failed/cancelled;超时 dispatch 5 分钟、运行 2.5 小时;可重试 reason `runtime_offline/runtime_recovery/timeout`,最多 2 次且仅 issue/chat 源;`issue rerun` 起全新 session。

### 10.4 协作通信与集成

- **Inbox & subscriptions**:人类提醒中心;四种情况自动订阅(创建/被指派/评论/被 `@`);改派不自动退订;子 issue 状态变更冒泡给父 issue 订阅者;**Agent 永不收通知**。
- **GitHub integration**:Settings→Integrations 装一次 GitHub App;PR 分支/标题/正文含 `MUL-123` 即自动关联,合并 PR 自动把非 done/cancelled 的 issue 移到 Done;只读权限只镜像 PR;自托管需建 App + 配 secret + 跑迁移 079。

### 10.5 账户、团队与运维

- **Auth setup**:邮箱验证码(Resend 或 SMTP;都没配则码写 stdout)+ 可选 Google OAuth;签名注册三层 AND `ALLOWED_EMAILS`>`ALLOWED_EMAIL_DOMAINS`>`ALLOW_SIGNUP`。
- **Auth tokens**:JWT cookie / PAT `mul_`(全文仅创建时显示一次,只存 hash)/ daemon token `mdt_`;泄露要 revoke 而非仅登出。
- **Desktop app**:原生多 tab、自动启 daemon、后台自更新;默认 Cloud,`~/.multica/desktop.json` 指自托管。
- **Quickstart**:Cloud 5 分钟(注册→装 CLI→`multica setup`→建 agent→指派);Self-host 用 Docker Compose。

## 11. 本地 vs 云双运行时

| 维度 | 本地 daemon runtime(生产可用) | 云 runtime(waitlist,未上线) |
|---|---|---|
| 执行位置 | 你自己机器,daemon 驱动本地 AI CLI | Multica Cloud 直接执行 |
| 是否需本机常驻 | 需要(`multica daemon start` 或 desktop 自启) | 不需要 |
| API key/代码/工具链 | 全留本机,服务端从不接触 | (未来) |
| 适用场景 | 现在所有用户;需用本地工具链/私有代码/已有 AI 订阅 | 上线后:纯托管 |

核心架构判断:server 只协调(存数据、排任务、WS 推送),**从不执行 agent 任务**;daemon 在你机器拾取任务驱动 AI 工具;AI 工具实际写代码。

## 13. 关键设计决策与硬约束速查

| 主题 | 约束 |
|---|---|
| 包边界 | `views → core + ui`;core 零 react-dom/localStorage/process.env;ui 零 `@multica/core`;views 零 `next/*`/`react-router-dom`/store |
| 无重复规则 | 同逻辑出现在两 app 必须抽到共享包 |
| 状态管理 | 服务端态全归 TanStack Query(以 `wsId` 起 key);客户端态全归 Zustand(全在 core);WS 事件只 invalidate query 不写 store;不把服务端数据复制进 store |
| API 响应兼容 | 不裸 `as` 转换响应体;用 `parseWithFallback` + zod + 显式 fallback;到处 optional-chain + 默认值;枚举漂移降级不崩;新增/改端点同 PR 加 schema + malformed 测试 |
| UUID 解析 | 标识符/UUID 路径参数经 loader 解析后用 `entity.ID`;纯 UUID 边界用 `parseUUIDOrBadRequest`;可信回程用 panic 变体 `parseUUID` |
| 全局路由命名 | 单词(`/login`)或 `/{noun}/{verb}`(`/workspaces/new`);禁连字符词组根路由;保留 slug 单一来源 `reserved_slugs.json` |
| Desktop 路由分类 | session 路由(tab 目标)/ 转场流程(WindowOverlay,非路由)/ 错误态(自愈,非页面);新预工作区流程注册 overlay 不加 `routes.tsx` |
| Desktop 工作区上下文 | `setCurrentWorkspace(slug,uuid)` 是唯一真相源;离开工作区须显式 `setCurrentWorkspace(null,null)`;销毁性操作严格顺序(读目的地→清上下文→导航→再 mutate) |
| CSS | 只用语义令牌(`bg-background`),禁硬编码 Tailwind 色;共享样式不在 app 重复 |
| 注释 | 代码注释仅英文 |
| 兼容层 | 除非显式要求,内部非边界代码不加兼容层/回退/双写/legacy adapter;API 边界除外(defensive,非 legacy shim) |
| 命名/i18n 真相源 | `apps/docs/content/docs/developers/conventions.mdx`(中英),写翻译/命名前先读 |
